# ADR-052: LadybugDB Replaces FalkorDB for Knowledge Graph Storage (2026-03-29)

**Context:**
- ADR-035 established FalkorDB (via FalkorDBLite) as the embedded graph database for the context graph
- FalkorDB requires a Redis server process (FalkorDBLite wraps Redis), port management, PID file cleanup, BGSAVE for persistence, and `redis-py` as a dependency
- KuzuDB was the other graphiti backend but was acquired by Apple in October 2025 and its GitHub repo archived
- LadybugDB (`real-ladybug` on PyPI) is the community fork of KuzuDB, maintained by ex-Facebook/Google engineers, API-compatible with Kuzu v0.11.3+
- Liminis is a local-first desktop app — an embedded database with no external processes is architecturally cleaner

**Decision:**
Replace FalkorDB with **LadybugDB** as the embedded graph database for the knowledge graph. A new `LadybugDriver` in the verveguy/graphiti fork provides drop-in compatibility with graphiti's driver protocol, reusing all existing Kuzu operation files unchanged.

**Architecture:**

```
Before (FalkorDB):
  graphiti_service.py → FalkorDriver → FalkorDBLite → Redis server (port 16379)
  Dependencies: falkordblite, redis-py, falkordb

After (LadybugDB):
  graphiti_service.py → LadybugDriver → LadybugDB (embedded, file path)
  Dependencies: real-ladybug (single package, no server)
```

**Key Design Decisions:**

1. **`provider = GraphProvider.KUZU`**: LadybugDriver keeps the KUZU provider enum so all KUZU-specific branches in graphiti (RelatesToNode_ intermediate nodes, brute-force vector search, Cypher dialect) continue to fire without changes.

2. **Reuse all Kuzu operations unchanged**: The `graphiti_core/driver/kuzu/operations/` subpackage only speaks Cypher and the graphiti driver protocol — no `kuzu` import. LadybugDriver delegates to these operations as-is.

3. **FTS extension per-connection**: LadybugDB loads extensions per-connection, not per-database. `build_indices_and_constraints()` explicitly loads the FTS extension on the async connection and creates all four fulltext indexes (Entity, Episodic, Community, RelatesToNode_).

4. **Timezone fix**: LadybugDB returns TIMESTAMP columns as naive datetimes. A `_fix_record_timestamps()` helper normalises all naive datetime values to UTC, fixing graphiti issue #893/#920 where comparisons against timezone-aware datetimes would crash.

5. **None params preserved**: Unlike the original KuzuDriver which stripped `None` values from query parameters, LadybugDriver passes them through. Kuzu requires all referenced `$params` to be present even when NULL — stripping them caused edge saves to fail silently.

6. **WAL support**: Full mutation logging via `WalWriter` (same pattern as FalkorDriver) plus `replay_wal_ladybug()` for database reconstruction from JSONL files. WAL dump from existing DB not yet implemented (uses FalkorDB-specific Cypher introspection).

7. **No stale state cleanup needed**: FalkorDBLite required PID file cleanup, stale socket removal, and port killing on restart. LadybugDB is a simple file — open it, use it. File locking is handled by the OS.

**What was eliminated:**
- `import redis` and redis-py monkey-patch
- `_kill_port()` — no port to manage
- `_cleanup_stale_db_state()` — no PID files or settings sidecar
- `_flush_to_disk()` / `BGSAVE` — LadybugDB auto-persists
- `EmbeddedFalkorDB` lifecycle (start/stop/close)
- `falkordblite` and `redis>=5.0` dependencies

**Known Limitations:**

1. **Brute-force vector search**: Uses in-memory numpy cosine similarity (same as original KuzuDriver). Adequate at current scale (~500 entities) but will need LadybugDB's vector index extension at 100K+ entities.

2. **WAL dump not implemented**: Cannot export existing DB state to WAL files (requires Kuzu-dialect Cypher introspection to replace FalkorDB's `labels()`, `properties()`, `vecf32()`). WAL logging during ingestion works.

3. **Stale process on unclean shutdown**: LadybugDB uses OS-level advisory locks (flock/fcntl) on the single `db` binary file — there is no separate lock sidecar. These locks are released automatically when the process terminates. If the service crashes, the lock is gone as soon as the OS reclaims the process. Stale process detection and cleanup (SIGTERM → SIGKILL on next startup, workspace-scoped PID file at `<workspace>/.liminis/graphiti_service.pid`) is implemented in issue #586.

4. **Direct Cypher queries in graphiti_service.py**: ~30 direct Cypher queries (status counts, entity merging, corrections) use FalkorDB Cypher dialect. Most work with Kuzu but some may need syntax adjustments.
