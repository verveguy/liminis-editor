# ADR-021: MCP OAuth Token Management (2026-01-28, updated 2026-03-17)

> **Partially superseded by [ADR-044](./adr-044.md)** (Deprecate Cursor IDE MCP Compatibility) — `.cursor/mcp.json` generation is no longer performed; only `.mcp.json` is used.

**Context:**
- MCP servers (like Atlassian Confluence) require OAuth 2.1 authentication
- OAuth flow returns access tokens (short-lived), refresh tokens (long-lived), and metadata (expiration, scope)
- The Claude Agent SDK does NOT automatically handle OAuth - applications must manage tokens manually
- Need to persist OAuth credentials across app restarts
- Need to refresh access tokens when they expire without re-authenticating
- The SDK only reads `.mcp.json` for server configuration - it does NOT read OAuth credentials from a separate file
- Initially misunderstood SDK behavior and thought it would read `.claude/mcp-oauth.json` (it doesn't)

**Decision:**
- Store OAuth credentials in `.liminis/mcp-oauth.json` (custom Liminis file, not part of Claude SDK)
- Structure: `{ credentials: { [serverName]: { serverUrl, accessToken, refreshToken, expiresAt, tokenType, scope } } }`
- Inject current access tokens into `.mcp.json` headers when regenerating runtime config
- Check token expiration (with 5-minute buffer) before injecting
- Normalize token type to "Bearer" (capital B) for OAuth 2.0 compliance
- Keep refresh tokens and OAuth metadata separate from runtime `.mcp.json` for security
- ~~Generate both `.mcp.json` (workspace root) and `.cursor/mcp.json` (Cursor IDE compatibility)~~ → Now generates only `.mcp.json` (see [ADR-044](./adr-044.md))

**Key Facts:**
- **The SDK does NOT read `mcp-oauth.json`** - This is a Liminis-specific file format we created
- **The SDK does NOT manage OAuth** - We must handle the complete OAuth lifecycle (flow, storage, refresh, injection)
- **The SDK ONLY reads `.mcp.json`** - It expects access tokens already injected into server `headers.Authorization`
- **OAuth tokens must be in header format** - `Authorization: Bearer <accessToken>` (capital B required by many servers)
- **SDK documentation quote:** "The SDK doesn't handle OAuth flows automatically, but you can pass access tokens via headers after completing the OAuth flow in your application"

**OAuth Workflow:**
1. User clicks "Authorize" in MCP settings → `performOAuthFlow()` opens browser for authentication
2. OAuth server redirects with authorization code → Exchange for access/refresh tokens
3. Save full credentials to `.liminis/mcp-oauth.json` (includes `refreshToken` for future use)
4. Call `regenerateRuntimeConfig()` → Injects current `accessToken` into `.mcp.json` headers
5. SDK reads `.mcp.json` → Connects to MCP server with injected token
6. SDK reads `.mcp.json` → Connects to MCP server with injected token
6. Before each SDK query, check token expiration → If expired, use `refreshToken` to get new token → Update storage → Regenerate `.mcp.json`

**Alternatives Considered:**
- Store OAuth tokens only in `.mcp.json` → Rejected: Refresh tokens are sensitive, shouldn't be in runtime config; also harder to manage token lifecycle
- Let SDK manage OAuth → Rejected: SDK doesn't provide this functionality
- Use OS keychain for token storage → Rejected: Complex cross-platform implementation, can't easily coordinate with runtime config generation
- Store in `.claude/` directory → Rejected: Misleading - implies Claude SDK uses it (it doesn't)

**Consequences:**
- ✅ Complete control over OAuth lifecycle (flow, storage, refresh, injection)
- ✅ Refresh tokens stored securely, separate from runtime config
- ✅ Token expiration handled automatically with 5-minute buffer
- ✅ Bearer token normalization ensures compatibility with OAuth 2.0 servers
- ✅ Clear separation: `.liminis/mcp-oauth.json` = source of truth, `.mcp.json` = runtime config
- ❌ Manual token management complexity (refresh logic, expiration tracking)
- ❌ Must regenerate `.mcp.json` whenever tokens are refreshed
- ❌ Token storage not encrypted at rest (file permissions set to 0600 for basic protection)

**Security Considerations:**
- File permissions set to 0600 (owner read/write only) on Unix systems
- Refresh tokens never included in `.mcp.json` (only current access token)
- Access tokens have limited lifetime (typically 1 hour)
- Users can revoke tokens via OAuth provider's settings

**File Locations:**
- `.liminis/mcp-oauth.json` - OAuth credentials storage (Liminis-specific, NOT read by SDK)
- `.mcp.json` - Runtime MCP config (read by Claude SDK, contains current access tokens in headers)
- ~~`.cursor/mcp.json` - Copy of runtime config (for Cursor IDE compatibility)~~ → Removed (see [ADR-044](./adr-044.md))
