# ADR-051: MLX-LM for Fully Local Knowledge Graph Indexing (2026-03-28)

**Updated:** 2026-03-29 — reflects LadybugDB migration (ADR-052) and embedding changes.

**Context:**
- Graphiti knowledge graph operations (entity extraction, relationship extraction, dedup, summaries) previously required Anthropic Claude API calls for all LLM completions
- ADR-035 established Graphiti + FalkorDB as the knowledge graph foundation; this decision addresses the LLM backend
- An intermediate `HybridLLMClient` attempted to offload `ModelSize.small` tasks (dedup, attributes, summaries) to Apple Foundation Models (AFM) via a Swift local-inference server over Unix domain socket
- AFM has a hard ~4096 token context limit, causing frequent fallbacks to Anthropic on prompts that include entity lists or previous messages — effectively negating the cost and offline benefits

**Decision:**
Replace all LLM completions with a single **Qwen3.5-9B** model running locally via `mlx-lm` in the Python process. One model handles both `ModelSize.small` (dedup, attributes, summaries, reclassification) and `ModelSize.medium` (entity extraction, relationship extraction) tasks. Anthropic becomes an optional fallback when `ANTHROPIC_API_KEY` is present.

**Note:** Spike testing (2026-03-29) revealed that Qwen 9B produces adequate dedup quality but noticeably weaker entity/relationship extraction compared to Anthropic Sonnet. Issue liminis-framework#112 tracks making the extraction LLM configurable at runtime so users can choose quality vs cost per task.

**Architecture:**

```
graphiti_service.py
├── _MLXLLMClient(LLMClient)    ← Primary: Qwen3.5-9B via mlx-lm, in-process
├── _FallbackLLMClient(LLMClient) ← Optional: wraps MLX + Anthropic
├── sentence-transformers        ← Embeddings: bge-base-en-v1.5 (CPU, 768-dim)
└── AnthropicClient              ← Fallback only (or sole provider on non-Apple Silicon)
```

**Key Design Decisions:**

1. **Single model for all tasks**: Qwen3.5-9B (~5GB at 4-bit quantization) handles both model size tiers. This keeps memory footprint low and avoids loading two models. Quality is sufficient for dedup but extraction benefits from a stronger model (see Note above).

2. **32K context window**: Qwen3.5-9B's context window eliminates the AFM bottleneck. The largest graphiti prompts (node dedup with growing entity lists) can now run locally without context overflow.

3. **Non-thinking mode**: Qwen3.5 supports hybrid thinking/non-thinking. We use `enable_thinking=False` via `apply_chat_template()` for direct JSON output without chain-of-thought overhead.

4. **Override `generate_response()` directly**: The base `LLMClient.generate_response()` appends raw JSON Schema to prompts, but small models respond better to concrete examples. We use `_schema_to_example()` (which converts Pydantic schemas to filled-in JSON examples) and handle prompt construction, validation, and retry ourselves.

5. **Built-in retry with validation feedback**: On JSON parse or Pydantic validation failure, the client retries once with the error message appended to the conversation. This improves reliability for fully-local mode where there's no Anthropic safety net.

6. **Generic fallback wrapper**: `_FallbackLLMClient` is a clean primary+fallback pattern (not specific to MLX+Anthropic). It deep-copies messages before the primary call so the fallback receives unmutated originals.

7. **Eager model loading at startup**: Model and tokenizer are loaded during `GraphitiService.initialize()`, not lazily on first call. This avoids multiprocessing/download conflicts in the async event loop and makes the first indexing call fast (~1s model already loaded).

8. **Metal GPU serialization**: A single-thread executor (`ThreadPoolExecutor(max_workers=1)`) serializes all MLX/Metal GPU operations for LLM generation. This prevents concurrent Metal command buffer encoding crashes.

9. **Sentence-transformers for embeddings**: Replaced the MLX embedding layer with `sentence-transformers` running `BAAI/bge-base-en-v1.5` on CPU (768-dim). This avoids the `transformers` version conflict between `mlx-embedding-models` (requires <5.x) and newer MLX model support (requires >=5.x). CPU embedding is fast enough (~3ms per embed) and runs concurrently with GPU LLM inference.

**Provider Selection Logic:**

| Apple Silicon + MLX | ANTHROPIC_API_KEY | Result |
|---------------------|-------------------|--------|
| Yes | Set | MLX primary, Anthropic fallback |
| Yes | Not set | MLX only (fully offline) |
| No | Set | Anthropic only |
| No | Not set | Error |

**Environment Variables:**

| Variable | Purpose |
|----------|---------|
| `MLX_LLM_MODEL` | Override default model (default: `mlx-community/Qwen3.5-9B-MLX-4bit`) |
| `ANTHROPIC_API_KEY` | Optional — enables Anthropic fallback |
| `GRAPHITI_LLM_MODEL` | Anthropic primary model for fallback (default: `claude-sonnet-4-5`) |
| `GRAPHITI_LLM_SMALL_MODEL` | Anthropic small model for fallback (default: `claude-haiku-4-5`) |
| `EMBEDDING_MODEL` | Sentence-transformers model name (default: `BAAI/bge-base-en-v1.5`) |

**Removed:** `LOCAL_LLM_SOCKET`, `LOCAL_LLM_MODEL`, `GRAPHITI_LLM_PROVIDER`

**Alternatives Considered:**

1. **Keep AFM + prompt splitting (graphiti#12)**: Split large prompts into chunks that fit in 4K context. Rejected — adds complexity, slows down indexing with multiple round-trips, and AFM's quality on structured JSON tasks is poor compared to Qwen3.5-9B.

2. **Two local models (4B for small, 9B for medium)**: Use Qwen3.5-4B for dedup tasks and 9B for extraction. Rejected — adds memory overhead for two models and complexity for marginal speed gain. The 9B model is fast enough on Apple Silicon for all tasks.

3. **Apple Foundation Models with NLContextualEmbedding**: Use Apple's newer APIs with better context handling. Rejected — still closed-source with undocumented limits, and the FoundationModels framework provides no structured output support.

4. **Outlines constrained generation**: Use the Outlines library for guaranteed-valid JSON output from MLX models. Deferred — the prompt-based approach with validation retry is simpler and sufficient. Can be added later if JSON compliance is a problem.

5. **MLX embedding models (bge-small via mlx-embedding-models)**: Running embeddings on Metal GPU alongside LLM. Replaced with CPU sentence-transformers due to `transformers` version conflict. CPU is fast enough and avoids GPU contention.

**Consequences:**

- Indexing works fully offline on Apple Silicon with zero API cost
- ~5.5GB GPU memory required (16GB+ Mac recommended)
- First inference call incurs ~1s model load time (eager loading)
- Quality of entity/relationship extraction is adequate but weaker than Claude Sonnet — configurable extraction LLM planned (liminis-framework#112)
- Non-Apple Silicon machines still require `ANTHROPIC_API_KEY`
- The Swift local-inference server (`local-inference/`) is no longer needed for completions
