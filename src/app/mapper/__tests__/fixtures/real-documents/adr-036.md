# ADR-036: Text Editor Tool Strategy - Using SDK Edit Tool (2026-02-20)

**Context:**
- Anthropic provides a native `text_editor_20250728` tool (`str_replace_based_edit_tool`) that supports token-efficient file editing via str_replace pattern
- The tool sends only changed text (old_str/new_str) rather than entire file contents
- Issue #200 requested implementing this tool for token efficiency benefits
- Investigation revealed the Claude Agent SDK already provides equivalent functionality

**Decision:**
- **Use the SDK's built-in `Edit` tool** instead of implementing `text_editor_20250728` directly
- The SDK's Edit tool (`FileEditInput` type) uses the same str_replace approach: `file_path`, `old_string`, `new_string`, `replace_all`
- No SDK modifications needed - token efficiency is already available

**Current Implementation (claude-agent.ts):**

```typescript
// allowedTools array - Edit is pre-authorized
const allowedTools: string[] = [
  '*',      // All built-in tools
  'Edit',   // Explicit entry (defensive)
  // ...
]

// PostToolUse hooks - Edit tracked for checkpoints
const fileWriteHookMatchers: HookCallbackMatcher[] = [
  {
    matcher: 'Write|Edit',  // Regex pattern matches Edit tool
    hooks: [handleFileWriteHook],
  },
]
```

**Token Efficiency Verification:**
- Edit tool sends only `old_string` and `new_string` parameters
- Estimated ~94x payload-size improvement for small edits to large files, based on JSON payload-size ratios from simulated requests
- See `docs/SDK.md` for methodology and examples

**Future Considerations - If SDK Adds Native text_editor_20250728:**

If the Claude Agent SDK adds support for Anthropic's native text_editor tool, the following changes would be needed:

1. **Tool Configuration** - Add to tools array in queryOptions:
   ```typescript
   tools: [
     { type: "text_editor_20250728", name: "str_replace_based_edit_tool" }
   ]
   ```

2. **Allowed Tools** - Add to allowedTools list:
   ```typescript
   const allowedTools: string[] = [
     '*',
     'str_replace_based_edit_tool',  // Add native tool name
     // ...
   ]
   ```

3. **Hook Matchers** - Extend the file write hook pattern:
   ```typescript
   const fileWriteHookMatchers: HookCallbackMatcher[] = [
     {
       matcher: 'Write|Edit|str_replace_based_edit_tool',  // Add new tool
       hooks: [handleFileWriteHook],
     },
   ]
   ```

4. **Stream Handler** - The existing `trackFileModifyingTool()` method already handles generic tool tracking:
   ```typescript
   // stream-handler.ts - no changes needed
   trackFileModifyingTool(toolUseID: string, toolName: string, filePath: string)
   ```

**Hook Extension Pattern:**

The PostToolUse hook system uses regex-based matchers. To add new file-modifying tools:

1. Add tool name to the `matcher` regex pattern (pipe-separated)
2. The `handleFileWriteHook` callback extracts `file_path` from tool input
3. Calls `trackFileModifyingTool()` for checkpoint annotation
4. Calls `addEditedFile()` to update the edited files panel

This pattern ensures:
- File checkpoints are created for any file-modifying tool
- Revision history tracks all file changes
- UI can display tool results with diff preview

**Alternatives Considered:**
- Implement text_editor_20250728 directly → Rejected: SDK doesn't support this tool type, and Edit provides equivalent functionality
- Replace Edit with text_editor → Rejected: SDK Edit tool is already integrated and working
- Wait for SDK to add native support → Rejected: Current Edit tool satisfies all requirements

**Consequences:**
- ✅ Token efficiency already available via existing Edit tool
- ✅ No code changes needed for basic functionality
- ✅ Clear path for future SDK updates
- ✅ PostToolUse hook pattern is extensible
- ✅ Checkpoint tracking works with current implementation
- ❌ Limited to SDK's Edit tool parameters (no view/insert commands)
- ❌ No undo_edit support (not supported in Claude 4 models anyway)
