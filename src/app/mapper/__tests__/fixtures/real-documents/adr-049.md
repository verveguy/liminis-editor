# ADR-049: Write-Ahead Log (WAL) for Knowledge Graph Backup (2026-03-25)

**Context:**
- The Graphiti knowledge graph database (`.lcg/db`) is a FalkorDB RDB binary that's too large for git (can reach 150MB+)
- Reconstructing the database requires LLM extraction calls — expensive in both time and API cost
- Workspace git repos using Graphiti cannot push because of the large binary file
- Users need a git-friendly way to back up and restore the knowledge graph

**Decision:**
Implement a write-ahead log (WAL) at the FalkorDB driver layer that captures every graph mutation as replayable JSONL files. The WAL becomes the git-tracked source of truth; the binary database is gitignored.

**Architecture:**

```
.lcg/
├── db              ← gitignored (FalkorDB binary, reconstructible)
├── db.settings     ← gitignored
├── wal/            ← git-tracked (replayable JSONL mutations)
│   ├── 20260325_140045_6df96f_0000.jsonl  (immutable after rotation)
│   ├── 20260325_140045_6df96f_0001.jsonl  (immutable after rotation)
│   └── 20260325_141812_6df96f_0004.jsonl  (active tip file)
└── *.log           ← gitignored
```

**Key Design Decisions:**

1. **Interception at driver layer**: All FalkorDB mutations flow through exactly two methods — `FalkorDriver.execute_query()` and `FalkorDriverSession.run()`. WAL logging is injected after successful execution, ensuring only committed mutations are logged.

2. **Mutation detection via keyword matching**: Cypher queries are classified as mutations by checking for CREATE/MERGE/SET/DELETE/DETACH/DROP/REMOVE keywords after stripping string literals. Intentionally permissive — false positives waste bytes, false negatives lose data.

3. **Index DDL excluded**: CREATE INDEX / DROP INDEX operations are filtered out because replay calls `build_indices_and_constraints()` separately. These are idempotent and schema-dependent.

4. **File rotation for git efficiency**: WAL files rotate after 50 events (~1MB per file). Completed files are immutable — git never sees the same file modified twice. New file on service start (new session UUID) ensures clean boundaries.

5. **Ownership model for shared WAL**: Cloned drivers (from `clone()` and decorators) share the WAL reference but don't own it. Only the original driver that created the WalWriter closes it. This prevents unbounded reference leaks from short-lived clones.

6. **Synchronous file I/O under async lock**: WAL writes use synchronous `open()`/`write()`/`flush()` inside an `asyncio.Lock`. This is intentional — local filesystem writes are microsecond-scale, and `aiofiles` would add thread-pool overhead for no measurable benefit.

7. **WAL behavior on graph clear**: The `knowledge_clear_all` handler supports two modes via the `preserve_wal` boolean parameter:
   - **WAL-deleting (`preserve_wal: false`)**: deletes both `.lcg/db` **and** `.lcg/wal/`. Used by `contextGraph:rebuildViaQueue` (Recreate button) to ensure a clean slate for re-ingestion — the pre-recreate WAL history is no longer meaningful and must not contaminate a subsequent Reload.
   - **WAL-preserving (`preserve_wal: true`)**: deletes `.lcg/db` only; leaves `.lcg/wal/` intact. Used by `contextGraph:clearGraph` (Clear button) so that WAL-based recovery (`knowledge_rebuild_from_wal`) remains available after a clear operation.

**Components:**

| Component | Location | Purpose |
|-----------|----------|---------|
| WalWriter | `graphiti_core/driver/wal.py` (graphiti fork) | Mutation logging with rotation and sequence continuity |
| WAL Replay | `graphiti_core/driver/wal_replay.py` (graphiti fork) | Reconstruct database from WAL files |
| WAL Dump | `graphiti_core/driver/wal_dump.py` (graphiti fork) | Export current DB state as WAL entries |
| Driver Integration | `graphiti_core/driver/falkordb_driver.py` (graphiti fork) | `wal_dir` param, instruments execute_query/session/clone/close |
| Service Integration | `.claude/skills/knowledge-graph/scripts/graphiti_service.py` (liminis-framework) | Passes `wal_dir` when constructing FalkorDriver |
| Dump CLI | `.claude/skills/knowledge-graph/scripts/dump_wal.py` (liminis-framework) | One-shot dump from workspace root |
| Load CLI | `.claude/skills/knowledge-graph/scripts/load_wal.py` (liminis-framework) | Restore database from WAL files |

**Usage:**

```bash
# Dump existing database to WAL (one-time bootstrap)
uv run .claude/skills/knowledge-graph/scripts/dump_wal.py

# Replay WAL to reconstruct database
uv run -m graphiti_core.driver.wal_replay .lcg/wal --host 127.0.0.1 --port 16379 --database liminis

# Dry-run replay (validate without executing)
uv run -m graphiti_core.driver.wal_replay .lcg/wal --dry-run
```

**JSONL Format:**
```json
{"seq":42,"ts":"2026-03-25T18:00:01.234Z","db":"liminis","cypher":"MERGE (n:Entity {uuid: $uuid}) SET n.name = $name","params":{"uuid":"abc-123","name":"Alice"}}
```
