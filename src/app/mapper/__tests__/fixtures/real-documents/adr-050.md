# ADR-050: macOS Code Signing and Notarization (2026-03-26)

> Builds on [ADR-001](./adr-001.md) (Electron Desktop Application) and [ADR-026](./adr-026.md) (macOS Code Signing and Python Subprocesses)

**Context:**
- The Liminis Notes Electron app had **no code signing infrastructure** — no signing identity, no entitlements, no notarization
- Without signing, macOS Gatekeeper blocks the app on any machine other than the development machine
- Issue #524 introduces a native Swift binary via `extraFiles`, making proper signing even more important for bundle integrity
- electron-builder v26.8.1 (already installed) includes `@electron/notarize` and `@electron/osx-sign` as transitive dependencies — no new packages needed
- ADR-026's `detached: true` workaround for Python subprocesses remains unchanged and out of scope

**Decision:**
Use electron-builder's **built-in notarization** support (the `notarize` config field, available since v24.13.3) with Developer ID distribution (not Mac App Store). Signing is configured entirely through `package.json` build config and environment variables — no custom `afterSign` scripts.

Key choices:
1. **Hardened Runtime** enabled with entitlements for V8 JIT, network access, file access, and Apple Events
2. **Two entitlements files**: `entitlements.mac.plist` for the main app, `entitlements.mac.inherit.plist` for helper processes and future native binaries (e.g., #524 Swift binary)
3. **Identity auto-discovery** — no explicit `identity` field; uses keychain (local) or `CSC_LINK` env var (CI)
4. **DMG signing disabled** — only the `.app` inside needs signing; DMG signing is unnecessary
5. **CI release via GitHub Actions** — tag-triggered workflow imports a `.p12` certificate into a temporary keychain, builds, signs, notarizes, and publishes to GitHub Releases

**Implementation:**

| Component | Change |
|-----------|--------|
| `liminis-app/package.json` `mac` block | Added `hardenedRuntime`, `gatekeeperAssess`, `entitlements`, `entitlementsInherit`, `notarize` |
| `liminis-app/package.json` `dmg` block | Added `"sign": false` |
| `liminis-app/build/entitlements.mac.plist` | New file — main app entitlements (JIT, network, files, apple-events) |
| `liminis-app/build/entitlements.mac.inherit.plist` | New file — inherited entitlements for helpers (`security.inherit`) |
| `liminis-app/env.template` | New "Code Signing & Notarization" section documenting all env vars |
| `.github/workflows/release.yml` | New tag-triggered CI workflow for build, sign, notarize, publish |

**Entitlement rationale:**

| Entitlement | Why |
|-------------|-----|
| `cs.allow-jit` | V8 JIT compilation |
| `cs.allow-unsigned-executable-memory` | V8 generates executable code at runtime |
| `cs.disable-library-validation` | Load Electron dylibs and unsigned Python native extensions |
| `network.client` / `network.server` | Anthropic API, InstantDB, local context graph server |
| `files.user-selected.read-write` | File open/save dialogs |
| `automation.apple-events` | `osascript` calls in `fs-handlers.ts` |
| `security.inherit` (inherit plist only) | Child processes inherit parent entitlements |

**Alternatives considered:**
- **Custom `afterSign` script**: More flexible but unnecessary — electron-builder's built-in `notarize` field handles the standard case. Avoids maintenance burden of a custom script.
- **Mac App Store distribution**: Rejected — MAS sandboxing is too restrictive for an Electron app that spawns Python subprocesses, runs local servers, and uses Apple Events. Developer ID distribution is the correct path.
- **Apple ID + app-specific password for notarization**: Replaced by App Store Connect API Key approach, which doesn't expire and doesn't require 2FA — better for CI.

**Consequences:**
- `pnpm package` on a Mac with a valid Developer ID certificate produces a signed and notarized `.dmg` and `.zip`
- Pushing a `v*.*.*` tag triggers CI release with automatic signing, notarization, and GitHub Release publishing
- When #524 adds a Swift binary via `extraFiles`, `@electron/osx-sign` automatically signs it during the bundle walk using `entitlementsInherit`
- The Apple Developer Team ID is provided via the `APPLE_TEAM_ID` environment variable used by the release workflow and electron-builder's `"notarize": true` config
- Seven GitHub repository secrets must be configured: `BUILD_CERTIFICATE_BASE64`, `P12_PASSWORD`, `KEYCHAIN_PASSWORD`, `APPLE_API_KEY`, `APPLE_API_KEY_ID`, `APPLE_API_ISSUER`, `APPLE_TEAM_ID`
